# LilaMD 0.6–0.7: таблицы с переносом, масштаб, своя панель табов

## Context
Стас использует LilaMD как основной просмотрщик `.md`. Сейчас ему мешают три вещи:
1. Длинный текст в ячейке таблицы уходит вправо, приходится листать вбок.
2. Нельзя увеличить или уменьшить текст.
3. Каждый файл открывается отдельным окном, переключаться неудобно.

Причины в коде:
- Таблицы: Vditor CSS (`Resources/vditor/dist/index.css`) — у `td/th` стоит `white-space: nowrap`, у `table` — `display:block; overflow:auto`.
- Масштаба нет. ⌘= и ⌘− в Vditor заняты: в таблице это добавить/удалить строку (`index.js:10631–10655`), в заголовке — сменить уровень (`index.js:5804`, `6919`).
- `MDEditorApp` построен на `DocumentGroup`: один документ = одно `NSWindow`.

Решения Стаса (04.11):
- Масштаб: ⌘= / ⌘− / ⌘0, общий на всё приложение, запоминается.
- Табы: своя панель внутри одного окна, не системные вкладки macOS.

Порядок поставки: таблицы → масштаб → табы. Это от простого к сложному, каждая часть — отдельный релиз.

## 1. Перенос текста в ячейках таблицы (0.6, ~0,5 дня)

**Требование.** В визуальном режиме текст ячейки переносится на следующую строку внутри ячейки. Горизонтальная прокрутка остаётся только если колонок так много, что они не помещаются даже с переносом.

**Изменение** — только `Resources/web/editor.css`:
```css
.vditor-reset table td, .vditor-reset table th { white-space: normal; overflow-wrap: anywhere; min-width: 4em; }
```
`display:block; overflow:auto` у `table` оставить — это запасная прокрутка для очень широких таблиц.

Режим «Исходник» не трогаем: в задаче речь о режиме отображения.

Файл `.md` не меняется: правка только в отображении, `SourcePreserver` её не видит.

**Проверка:**
- Новый `samples/wide-table.md`: длинный абзац в ячейке, URL без пробелов, таблица на 12 колонок.
- XCTest (`Round4Tests`): у ячейки `getComputedStyle(td).whiteSpace == "normal"`, `scrollWidth` таблицы ≤ ширины редактора для 3-колоночной таблицы с длинным текстом.
- Регресс: тесты `Round2Tests`/`Round3Tests` (каретка в первой ячейке, ввод в таблице в начале документа) проходят.
- Скриншот окна 1100×800 до/после.

## 2. Масштаб текста (0.6, ~1 день)

**Требование.**
- Меню View: Zoom In (⌘=), Zoom Out (⌘−), Actual Size (⌘0), подменю Zoom с пунктами 80 / 90 / 100 / 110 / 120 / 150 % и галочкой у текущего.
- ⌘= / ⌘− ходят по этой же лестнице и останавливаются на 80 % и 150 %. Пункт меню на краю неактивен.
- Масштаб общий для всех окон/табов, переживает перезапуск. По умолчанию 100 %.
- Работает в обоих режимах (Visual и Source).

**Реализация:**
- Новый `Sources/Zoom.swift`: `enum ZoomPreference` по образцу `EditorModePreference` (`EditorMode.swift`) — ключ `editorZoom`, список ступеней, `next/previous`.
- `MDEditorApp.swift`: `@AppStorage("editorZoom")`, `CommandGroup(after: .toolbar)` с пунктами меню рядом с Visual/Source.
- `EditorView.swift`: `zoom` передаётся в `EditorView`, в `updateNSView` → `controller.setZoom(_:)`.
- `EditorController.swift`: `setZoom` ставит `webView.pageZoom`. Нативное свойство, без JS. Масштабирует и шрифт, и отступы, как в Safari.
- **Перенос хоткеев Vditor на ⌥⌘= / ⌥⌘−.** Пункт меню ⌘= перехватит клавишу до страницы (так уже работает с ⌘Z). Чтобы не потерять «добавить/удалить строку таблицы» и «сменить уровень заголовка», в `editor.js` (`speedUp`) добавить keydown-перехватчик: на ⌥⌘= / ⌥⌘− отправить в редактор синтетический `KeyboardEvent` с `key: "="`/`"-"` и `metaKey: true`. Vditor сам выберет действие по месту каретки. ⇧⌘= / ⇧⌘− (колонки) не меняются.
  - Перед реализацией проверить, что ⌥⌘= / ⌥⌘− свободны в Vditor (`grep "⌥⌘" index.js`) и что `matchHotKey` принимает синтетическое событие.
- Обновить раздел «Решения» в `docs/DEVELOPMENT.ru.md` и README: новые клавиши, перенос табличных.

**Проверка:**
- XCTest: `setZoom(1.5)` → `webView.pageZoom == 1.5`; лестница `next/previous` на краях.
- XCTest через настоящие `NSEvent` (как в `Round3Tests`): ⌘= в ячейке таблицы меняет масштаб и не добавляет строку. ⌥⌘= в ячейке добавляет строку. После Cmd+S diff файла — только новая строка (сценарий T4 из `DEVELOPMENT.ru.md:189`, клавиша теперь ⌥⌘=).
- Тесты круга 3, где сейчас жмётся ⌘= в таблице, перевести на ⌥⌘=.
- Вручную: 150 % на `big.md` — набор текста без заметных лагов (C6-замер, медиана ≤ текущих ~31 мс). Подсказки Vditor (автодополнение) открываются у каретки, а не со сдвигом.
- Перезапуск приложения → масштаб сохранился.

## 3. Своя панель табов (0.7, ~1–2 недели, главный риск)

**Требование (MVP):**
- Одно главное окно. Новый документ открывается табом в нём. Это касается всех способов открытия: Finder (двойной клик, `open -a`), File → Open, ⌘N, перетаскивание файла на окно.
- Полоса табов над редактором. Таб показывает имя файла, точку «не сохранено» и × при наведении.
- Уже открытый файл не дублируется: фокус переходит на его таб.
- Переключение: клик, ⌃Tab / ⌃⇧Tab, ⇧⌘] / ⇧⌘[. ⌘1/⌘2 остаются за Visual/Source.
- ⌘W закрывает таб. Если есть несохранённые правки — вопрос «Сохранить?». Последний таб закрыт → окно закрывается.
- Контекстное меню таба: Close, Close Others, Close Tabs to the Right, Reveal in Finder, Copy Path.
- Перетаскивание табов мышью для смены порядка.
- Каждый таб держит свой `WKWebView`: undo-история и прокрутка не теряются при переключении. WebView создаётся при первом показе таба.
- Заголовок окна = имя активного файла, proxy-иконка (`window.representedURL`).

**После MVP (не делаем сейчас):** восстановление табов после перезапуска, вынос таба в отдельное окно, несколько окон с табами.

**Архитектура:**
- `MDEditorApp`: `DocumentGroup` → один `Window` + `@NSApplicationDelegateAdaptor`. Делегат ловит `application(_:open:)` (Finder, `open -a`) и `applicationShouldTerminate` (несохранённые табы).
- Новый `Sources/TabStore.swift`: `@MainActor final class TabStore: ObservableObject` — массив `OpenDocument`, `activeID`, `open(url:)`, `newUntitled()`, `close(id:)`, `move(from:to:)`.
- Новый `Sources/OpenDocument.swift`: `url`, `text`, `savedData`, `isDirty`, ленивый `EditorController`, `FileWatcher`. Чтение и запись байтов — через существующие `MarkdownDocument(data:)` и `data()`, чтобы BOM, CRLF и ошибка «не UTF-8» работали как сейчас.
- Новый `Sources/TabBarView.swift`: полоса табов на SwiftUI.
- `EditorView.swift`: `DocumentWindow` → `TabbedWindow` (полоса + `ZStack` из `EditorView` всех открытых табов, видим только активный).
- `FileWatcher.swift`: вместо `NSDocumentController.document(for:)` / `revert` — колбэки `isDirty` / `reload(from:)` от `OpenDocument`. Диалог `makeConflictAlert` не меняется.
- `EditorController.forKeyWindow()` → брать контроллер активного таба из `TabStore`. Иначе Undo/Redo из меню попадёт в скрытый WebView.
- Меню File: New (⌘N), Open (⌘O), Open Recent (`NSDocumentController.noteNewRecentDocumentURL`), Save (⌘S), Save As (⇧⌘S), Close Tab (⌘W).
- Сохранение — атомарная запись. Перед записью проверить, что файл на диске не изменился с момента загрузки. Если изменился — спросить. Сейчас это даёт `NSDocument`.

**Что `DocumentGroup` даёт сейчас, а мы теряем или делаем сами** — проверить на шаге 0:
- автосохранение (SwiftUI-документы на macOS по умолчанию сохраняются сами),
- Versions («Вернуться к…» / «Просмотреть все версии»),
- переименование и перемещение файла из заголовка окна,
- вопрос «Сохранить изменения?» при закрытии и выходе.

**План работ (шаг → проверка):**
0. Записать фактическое поведение текущей сборки по списку выше → таблица «было / будет» в `DEVELOPMENT.ru.md`. Автосохранение, если есть, сохраняем.
1. `OpenDocument` + `TabStore` без UI → XCTest: open/close/dedupe/dirty, байты при сохранении нетронутого файла совпадают с исходными (CRLF, BOM, `samples/*`).
2. `TabbedWindow` + `TabBarView`, замена `DocumentGroup` → вручную: открыть 3 файла из Finder, все три в одном окне.
3. Сохранение, закрытие, выход с несохранёнными правками → XCTest + ручной прогон диалогов.
4. `FileWatcher` на новых колбэках → существующий тест C7 и тест диалога конфликта проходят.
5. Меню, хоткеи переключения, контекстное меню, перетаскивание → ручной чек-лист.
6. Обновить `scripts/smoke.sh`: сценарии, где ожидалось новое окно на файл, теперь ждут таб. `windowid.swift` ищет одно окно.

**Проверка всего раздела:**
- Все 48 существующих тестов зелёные (`xcodebuild ... test`). `EditorHarness` в `Tests/Support.swift` работает с `EditorController` напрямую, на него переход не влияет.
- `scripts/smoke.sh` зелёный.
- Память: 10 табов с `big.md` → RSS приложения записать в `DEVELOPMENT.ru.md`. Если > 1,5 ГБ — выгружать WebView неактивных табов.

## Риски
- **Табы — самый крупный риск регрессий.** Сохранение байт-в-байт, конфликт-диалог и undo сейчас опираются на `NSDocument`. Митигация: шаг 0 и тесты на байты до замены UI.
- **⌘= / ⌘− меняют смысл.** Кто привык добавлять строку таблицы по ⌘=, получит масштаб. Митигация: строка в README и пункт меню с подсказкой ⌥⌘=.
- **`pageZoom` и всплывающие элементы Vditor.** Позиционирование подсказок может съехать. Запасной вариант — CSS-переменная `font-size` для `.vditor-reset` и `.vditor-sv`.

## Критерий готовности
- Таблица с длинным текстом читается без горизонтальной прокрутки при окне 1100×800.
- ⌘= / ⌘− / ⌘0 и пункты 80–150 % работают, масштаб пережил перезапуск, ⌥⌘= добавляет строку таблицы.
- Пять файлов из Finder открылись табами в одном окне. Сохранение нетронутого файла даёт исходные байты. Закрытие таба с правками спрашивает «Сохранить?».
- Тесты и смоук зелёные, `DEVELOPMENT.ru.md` обновлён.
