# LilaMD 1.0: первый релиз в Mac App Store

## Context
Сейчас LilaMD распространяется через GitHub Releases и `install.sh`. Сборка подписана ad-hoc, без песочницы и без нотаризации, поэтому Gatekeeper блокирует DMG.

Цель 1.0 — опубликовать приложение в Mac App Store. Модель: бесплатно + донат.

Исследование рынка (11.11.2026):
- Главный прямой конкурент — Clearly Markdown: бесплатный, нативный, open source. В нём редактор с подсветкой синтаксиса и отдельным превью, правки в отформатированном виде нет.
- Typora ($14.99) — лидер правки в отформатированном виде, но в Mac App Store её нет.
- Быстрее всех из новичков 2026 года растёт Read.md: просмотрщик `.md` для файлов, которые пишут AI-агенты (118 оценок за 7 месяцев).
- Пользователи просят возможность заплатить бесплатному приложению: «I can't throw money at the developer».
- Жалобы на конкурентов: потеря текста, падения при открытии перемещённого файла из Recents, ошибки метода ввода, поведение не по правилам macOS, недоверие к сгенерированным AI приложениям.

Позиционирование: «Open any Markdown file and edit it right in the rendered view». Опоры: вкладки, автосохранение как в Notes, работа без сети, открытый код.

Решения Стаса (11.11):
- Цена: бесплатно + донат. Pro-версия — после 1.0.
- В план входит подсветка активной вкладки: сейчас её не видно.

Порядок: этап 0 идёт параллельно с этапом 1. Этапы 2–5 ждут Team ID из этапа 0.

---

## 0. Аккаунт и договоры (Стас, параллельно с этапом 1)

Делает только Стас. Агент не может оформить это за него.

1. Apple Developer Program, аккаунт физлица: $99 в год, Apple ID с 2FA. Проверка занимает от нескольких часов до 2 дней.
2. App Store Connect → Business:
   - Paid Applications Agreement (нужен даже для бесплатного приложения с донатом);
   - банковский счёт;
   - налоговая форма W-8BEN.
3. Заявка в App Store Small Business Program: комиссия 15% вместо 30%.
4. **Решение по DSA (ЕС).** Донат — это монетизация. По разъяснениям Apple, монетизирующий разработчик скорее всего считается trader (сверить с формой в App Store Connect). Для trader Apple покажет адрес и телефон на странице приложения в ЕС. Варианты:
   - указать виртуальный адрес и отдельный номер;
   - не публиковать приложение в странах ЕС.

**Готово, когда:** агенту передан Team ID, договор Paid Apps в статусе Active.

## 1. Продукт: правки до ревью (агент, без аккаунта)

### 1.1 Подсветка активной вкладки (~0,5 дня)
**Проблема.** Фон активной вкладки (`Color(nsColor: .controlBackgroundColor)`, `Sources/TabBarView.swift:74`) почти совпадает с фоном полосы (`.bar`, строка 20). Активную вкладку не видно.

**Требование.** Активная вкладка с первого взгляда отличается от остальных:
- в светлой и тёмной теме;
- в активном и неактивном окне;
- при 2 и при 10 вкладках.

**Изменение.**
- Фон активной вкладки = фон редактора (`.textBackgroundColor`): вкладка сливается с документом, как в Safari и Xcode.
- Полоса цвета акцента 2 pt по верхнему краю.
- Заголовок с весом `.semibold`.
- В неактивном окне полоса акцента становится серой.

**Проверка.**
- Скриншоты 4 состояний: светлая/тёмная × активное/неактивное окно. Стас принимает по скриншотам.
- XCTest: у активного `TabItem` другой фон, чем у неактивного (через accessibility или снапшот).

### 1.2 Ввод на других языках (~0,5–2 дня)
**Риск.** У Clearly в отзывах тяжёлый баг с китайским вводом. Vditor работает в WebView и сам обрабатывает `compositionstart`/`compositionend`.

**Проверка.** Режим Visual. Раскладки: русская, китайская (Pinyin), японская (Kana). Места ввода:
- абзац;
- заголовок;
- ячейка таблицы;
- элемент списка;
- первая строка документа.

Критерий: нет задвоенных или потерянных символов, каретка остаётся на месте, автосохранение не срывает набор.

**Если найден баг** — исправить в `Resources/web/editor.js`, добавить регресс-тест.

### 1.3 Поведение по правилам macOS (~0,5 дня)
Проверить и исправить:
- About LilaMD: версия, коммит, ссылка на GitHub.
- Окно перетаскивается за полосу заголовка и за пустую часть полосы вкладок.
- File → Open Recent: файл перемещён или удалён → понятное сообщение, без падения (баг Read.md из отзывов).
- Settings: пункт уже убран (`MDEditorApp.swift:18–20`). Проверить, что в меню нет пустого Settings….
- Help → «LilaMD on GitHub», «Report an Issue».

### 1.4 Close Tab иногда не закрывает вкладку (~0,5–1 день)
Открытый хвост 0.6: 2 срабатывания из 46. Данные не теряются, но ревьюер Apple может наткнуться.

**Требование.** 0 срабатываний из 100 прогонов, проверка через AX.

### 1.5 Открытие из терминала (опционально, ~0,1 дня)
Просьба из отзывов на Read.md. Из песочницы приложение не может само поставить CLI. Вместо этого — строка в README:

`alias lilamd='open -a LilaMD'`

### 1.6 Проверить рендер Mermaid и формул (~0,2 дня)
Модули `mermaid` и `katex` лежат в `Resources/vditor/dist/js`, но рендер не проверялся. Если работает — упомянуть в описании. Если нет — не упоминать.

## 2. Песочница и подпись (агент, нужен Team ID, ~1–2 дня)

**Изменения в `project.yml`:**
- `ENABLE_APP_SANDBOX: YES`, файл `LilaMD.entitlements`:
  - `com.apple.security.app-sandbox`;
  - `com.apple.security.files.user-selected.read-write`;
  - `com.apple.security.files.bookmarks.app-scope` (для 2.1).
- `ENABLE_HARDENED_RUNTIME: YES`.
- `DEVELOPMENT_TEAM: <Team ID>`, `CODE_SIGN_STYLE: Automatic`.
- Info.plist: `ITSAppUsesNonExemptEncryption = NO`.

### 2.1 Картинки рядом с документом
**Проблема.** `mdedit://doc/<path>` читает файлы из папки документа (`Sources/SchemeHandler.swift:27`). Песочница даёт доступ только к открытому файлу, поэтому картинки из папки не загрузятся.

**Решение.**
- Если в документе есть локальная картинка и её не удалось прочитать, над редактором появляется полоса: «Images in this folder are blocked. Allow access…».
- Кнопка открывает `NSOpenPanel` на папке документа.
- Доступ сохраняется как security-scoped bookmark на папку. Следующие документы из этой папки и её подпапок открываются с картинками без вопроса.

**Проверка.** `samples/` с картинкой:
1. первое открытие → полоса;
2. разрешение → картинка видна;
3. перезапуск → картинка видна без вопроса.

### 2.2 Регресс под песочницей
Каждый пункт — отдельный тест или ручная проверка со скриншотом:
- открытие двойным кликом в Finder, через Open… и перетаскиванием на полосу вкладок;
- автосохранение существующего файла: `replaceFile` через `itemReplacementDirectory` (`Sources/OpenDocument.swift:208`) — главный риск;
- Save As в новую папку;
- обнаружение изменения файла снаружи (конфликт);
- Reveal in Finder, открытие ссылок в браузере;
- Open Recent после перезапуска;
- приложение по умолчанию для `.md`.

**Учесть.** Под песочницей `UserDefaults` переезжают в контейнер. Масштаб и режим у Стаса один раз сбросятся.

### 2.3 Канал GitHub
Сборка для GitHub тоже подписывается Developer ID и нотаризуется: Gatekeeper перестанет блокировать DMG. Код тот же, песочница остаётся.
- `scripts/package.sh`: добавить `notarytool submit --wait` и `stapler staple`.
- `install.sh` не меняется.

## 3. Донат (агент, нужен договор Paid Apps, ~1 день)

- StoreKit 2. Три расходуемые покупки:
  - `com.drkhwo.lilamd.tip.small` — $0.99;
  - `com.drkhwo.lilamd.tip.medium` — $2.99;
  - `com.drkhwo.lilamd.tip.large` — $4.99.
- Пункт меню LilaMD → «Support LilaMD…»: окно с тремя кнопками и строкой «Tips don't unlock anything. LilaMD stays free.»
- После покупки — «Thank you!». Ничего не открывается и не меняется: так требует правило Apple для чаевых.
- Никаких напоминаний и всплывающих окон с просьбой о донате.
- `LilaMD.storekit` для локальных тестов + покупка sandbox-тестером в TestFlight.
- В сборку для GitHub пункт не попадает (флаг сборки): там покупки через App Store невозможны.

**Проверка:** покупка каждого из трёх уровней sandbox-тестером, отмена покупки, нет сети.

## 4. Карточка в App Store Connect (агент готовит, Стас вводит)

| Поле | Значение |
|---|---|
| Название (≤30) | `LilaMD: Markdown Editor` |
| Подзаголовок (≤30) | `Edit .md files as they look` |
| Ключевые слова (≤100) | `md,reader,viewer,wysiwyg,writer,notes,preview,readme,docs,text,tabs,offline,ai,agent,write` |
| Категория | Productivity, вторая — Developer Tools |
| Цена | Free |
| Возраст | 4+ |
| Приватность | Data Not Collected |
| Privacy Policy URL | GitHub Pages: `docs/privacy.md` |
| Support URL | GitHub Issues |

**Ключевые слова.** Чужие бренды (Typora, Obsidian, Claude) не ставить: Apple отклоняет за это.

**Описание — первые строки:**
«Open any Markdown file and edit it right in the rendered view — no split pane, no syntax noise. Tabs, autosave like Notes, works fully offline. Open source, no account, no tracking.»

**Скриншоты** (2880×1800, 4 штуки):
1. `.md` от AI-агента открыт двойным кликом;
2. правка таблицы прямо в отформатированном виде;
3. несколько вкладок, активная хорошо видна (после 1.1);
4. тёмная тема.

**Готово, когда:** все поля заполнены, `docs/privacy.md` опубликован, скриншоты сняты на сборке-кандидате.

## 5. Сборка, TestFlight, ревью (~1 день работы + ожидание)

1. `scripts/appstore.sh`:
   - `xcodebuild archive`;
   - `xcodebuild -exportArchive` с `method = app-store-connect`;
   - загрузка через `xcrun altool --upload-app` или Transporter.
2. TestFlight for Mac: Стас ставит сборку и неделю пользуется ею как основным редактором.
3. Отправка на ревью с ручным выпуском (Manually release).
4. Отказ ревью → исправить, отправить снова. Обычно ревью занимает 1–3 дня.
5. Выпуск: релиз 1.0 одновременно в App Store и в GitHub Releases, release notes в `docs/releases/v1.0.0.md`.
