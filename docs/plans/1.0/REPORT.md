## Фоновый режим тестов

Причина: прежние прогоны `xcodebuild test` захватывали экран, клавиатуру и фокус Стаса, пока он работал.

- `scripts/test.sh` по умолчанию запускает тесты в фоне. Тесты, которым нужен экран, помечены `requireForeground` и пропускаются.
- Режим с экраном: `scripts/test.sh --foreground`. Его запускает только оркестратор, когда Стас отошёл.
- Шаги `scripts/fg/*` (реальные события, источники ввода, AX) в фоне не запускаются.
- Коммит: `4ed08c5`. Эксперименты: `E/bgmode/`.

## Найденные и исправленные баги

1. **Close Tab без ключевого окна.** Без ключевого окна пункт «File ▸ Close Tab» не закрывал вкладку. Проба в фоне до фикса: 0 из 100 (`E/CLOSE/bg-100-before-fix.log`). После фикса на `3b4e5b4`: 100 из 100, `keyWindow=nil isActive=false` (`E/CLOSE/bg-100-final.log`). Коммит `a18ade9`. С экраном (старый HEAD): ⌘W и меню по 100 из 100 (`E/CLOSE/fg/run.txt`, `E/CLOSE/fg-cmdw/run.txt`).
2. **Регрессия Undo после переключения вкладки.** Причина: фокус забрал переключатель Visual/Source. Фикс: после обновления вкладки фокус получает редактор показанной вкладки. Коммит `6670ec9`.
3. **База undo во время композиции IME.** Исправлена в `ebd5c07`.
4. **Return после композиции в ячейке таблицы.** Return, подтверждающий композицию, добавлял `<br />` в ячейку. Фикс в `editor.js`, коммит `44e1f14`. Красный прогон: без фикса `testIME4b` падает на `IMETests.swift:203` (`E/IME/red-4b.log`, `E/IME/red-4b.revert.diff`). Зелёный: `E/IME/green-4b.log`. Оговорка: тест шлёт Return как JS-событие (keyCode 229, isComposing false), не как настоящий Return из IME.
5. **Блочные формулы включены.** `mathBlockPreview: true`, решение Стаса. Коммит `033c8f4`. Проверка MER-5: правка внутри блока `$$`, затем undo. Тест сверяет точный текст после правки и после undo. Байты файла не меняются после правки, undo, сохранения и закрытия. Лог: `E/MER/mer5.log`. Оговорка: undo идёт через меню (`controller.undo()`), не через настоящий ⌘Z.
6. **Цвет активной вкладки (дефект продукта, пункт 1.1).** В тёмной теме страницу красит `pre.vditor-reset` цветом `#24292e`, а вкладка использовала `#1d2125`. Фикс `925c729`: `EditorPalette.pageBackground` и `editor.css` в тёмной теме берут `#24292e`. Тест сравнивает вкладку с цветом из настоящего снимка WKWebView, допуск 3 на канал. До фикса тест падал в тёмной теме (`E/TAB/red-before-fix.log`). После: 5 из 5 (`E/TAB/test.log`). Тёмная вкладка (36,42,46) против страницы (36,41,46) в `E/TAB/render-values.txt`. Ошибка самого теста тоже исправлена: он читал пиксели как калиброванный RGB, теперь читает значения sRGB.
