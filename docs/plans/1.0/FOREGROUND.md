# LilaMD 1.0, этап 1: пакет шагов с экраном

Эти шаги забирают экран, клавиатуру, фокус или источник ввода. Разработчики их **не запускают**. Оркестратор запускает пакет целиком, когда Стас отошёл от Mac.

`E` = `/Users/stanislav/dev/QA/2026-11-11-lilamd-1.0`.

## Перед запуском

1. Стас не работает за Mac. Экран разблокирован.
2. Нет другого прогона тестов (`pgrep -fl xcodebuild` пуст).
3. Запомнить текущий источник ввода: шаги, которые его меняют, возвращают его сами, но итог сверяется в конце.

## Правила для шагов

- Один шаг = один скрипт `scripts/fg/<NN>-<имя>.sh`. Запуск из корня worktree.
- Скрипт идемпотентен: повторный запуск даёт тот же результат и чистит за собой прошлые файлы шага.
- Скрипт в конце возвращает исходное состояние: источник ввода, список включённых источников, закрытое Debug-приложение, временные файлы. Возврат — в `trap … EXIT`, чтобы сработал и при ошибке.
- Скрипт работает только с Debug-сборкой из `build/dd`. `/Applications/LilaMD.app` не трогать. `--args -MDEditorRecordsRecents NO`, если шаг не проверяет Open Recent.
- Скрипт пишет доказательства в `E/<task-id>/fg/` и печатает итог одной строкой: `RESULT <шаг> PASS|FAIL <детали>`. Код выхода 0 = PASS.
- Формат описания шага ниже: команда, ожидаемый результат, доказательство, ID критериев.

## Шаг 1. Полный прогон тестов на экране

- Команда: `scripts/fg/01-full-suite.sh`
- Что делает: `scripts/test.sh --foreground`, лог в `E/fg/test.log`.
- Ожидаемо: `** TEST SUCCEEDED **`, `Executed N tests, with K tests skipped and 0 failures`, N ≥ 146. K — только тесты «только для фона» (CLOSE-1), список в REPORT.
- Доказательство: `E/fg/test.log`.
- Критерии: REG-1, REG-3, REG-4, MER-5.

## Шаг 10. Подсветка активной вкладки: скриншоты, AX, прокрутка (D1)

- Команда: `scripts/fg/10-tab-screenshots.sh`
- Что делает: собирает Debug в `build/dd`, запускает его с 3, 2 и 10 файлами, `-MDEditorAppearance light|dark`, `-MDEditorRecordsRecents NO`. Активное окно: `open -a` приложения. Неактивное: `open -a Finder`, окно приложения остаётся на экране. Снимок `screencapture -x -o -l <windowid>` (`scripts/windowid.swift`). Затем читает настоящее AX-дерево через System Events. Для TAB-7 сужает окно до 420 pt и жмёт ⌃⇧Tab ×9, потом ⌃Tab ×9.
- Что берёт у Стаса: экран, фокус, клавиатуру на время шага (около 1–2 минут). Источник ввода не меняет.
- Возврат состояния (`trap … EXIT`): Debug-приложение закрыто, переднее приложение возвращено, временные файлы удалены. `/Applications/LilaMD.app` не тронут.
- Ожидаемо: `RESULT 10-tab-screenshots PASS`. Файлы:
  - `E/TAB/fg/{light,dark}-{active,inactive}.png` (TAB-4): активная вкладка видна с первого взгляда, полоса сверху акцентная в активном окне и серая в неактивном, фон вкладки сливается со страницей.
  - `E/TAB/fg/tabs-{2,10}-{light,dark}.png` (TAB-5).
  - `E/TAB/fg/ax-tabs.txt` (TAB-3 вживую): 3 строки `tab:<имя> selected=…`, ровно одна `selected=true`.
  - `E/TAB/fg/scroll-first.png`, `scroll-to-active.png` (TAB-7): на втором снимке активная (10-я) вкладка видна целиком.
- Вердикт «видно с первого взгляда» (TAB-4, TAB-5) и прокрутка (TAB-7) — глазами Стаса по PNG. Скрипт проверяет только, что снимки сняты и AX сходится.
- Риск: Stage Manager может показать окно полосой-миниатюрой, тогда снимок уже 300 px и скрипт скажет FAIL. Повторить с отключённым Stage Manager.
- Критерии: TAB-3 (вживую), TAB-4, TAB-5, TAB-7.
